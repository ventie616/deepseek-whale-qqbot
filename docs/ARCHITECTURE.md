# 架构与设计取舍

这份文档解释"为什么这么做"，而不是"怎么用"（用法看 README）。

---

## 1. 为什么不是一个 `消息 → LLM → 回复` 的机器人

那种机器人只解决"能回话"。这个项目解决的是四个更难的问题：

| 问题 | 我们的解法 |
|---|---|
| 回复像客服 | 人格 + 分条规则 + 禁用书面词 + 表情包 |
| 不知道聊过什么 | 群记忆（人物卡/摘要/她上一句）+ 聊天存档 |
| 不会主动做事 | 刷 B 站 + 评论 + 主动私聊 + 早晚仪式 |
| 越用越难调 | 规则蒸馏（`feedback_learner`） |

---

## 2. 刷 B 站：判据在管什么

```
候选 → [规则层] 搬运/抄袭关键词、标题相似度(7天) 
     → [内容层] 字幕原文 / 官方总结 / 抽帧画面 / 音频侦察
     → [判据层] YES|档位|理由   （档位：值得看 / 可以看 / 不值当）
     → [生成层] 两行评论：钩子 + 叫你来看
     → [复核层] 发完拉回来核对 rpid
```

**为什么要"档位"**：只有"发/不发"两态时，判据会反复摇摆。三档让模型有中间地带（可以看），也方便事后统计它到底挑剔到什么程度。

**为什么规则层先跑**：关键词和相似度是零 token 的，能在调模型之前砍掉一半垃圾。

**为什么评论要复核**：B 站会折叠/吞评论，`code 0` 不代表公开可见。我们发完 2 秒拉回来按 rpid 找。

## 3. 内容三层：为什么不是"直接看视频"

| 层 | 成本 | 什么时候用 |
|---|---|---|
| 字幕原文 | 0 | 有 CC/AI 字幕时（最可信） |
| 官方 AI 总结 | 0 | 没字幕时（二手信息） |
| 抽帧看画面 | ~1.8k token | 前两者都空，或 `vision_mode=always` |

**为什么不下载视频**：B 站自己提供 `videoshot`（10×10 精灵图），一次请求拿到整片缩略帧，不用下几十 MB。

**变化优先选帧**：把精灵图解出来，逐帧算灰度差（本地 CPU，零 token），再按"变化峰值 + 首尾覆盖 + 最小间距"挑 6 张。均匀采样会漏掉快动作，而且**说不清漏了什么**。

**音频侦察**：取 25 秒音频跑 `silencedetect + volumedetect`，只回答"有没有声音"。**不做 ASR**——参考项目实测过，纯 BGM 视频上 Whisper 会对三个互不重叠的时间窗输出完全相同的伪造字幕。既然听不准，就干脆只判"有没有声"，并且用提示词禁止模型提"解说"。

## 4. 记忆三层

```
聊天原文  ──▶ chat_archive（30 天，可检索）
                │
                ├─▶ 群摘要（每 24 条压一次，≤160 字）+ 人物卡（摘要时自动抽特征）
                │
B 站 视频 ──▶ bili_recent（6 小时，全部）
                │
                └─▶ bili_memory（长期，评论过的 / 值得看的 / 她主动 keep 的）
```

**为什么分短期/长期**：一天看 20 条，全进长期记忆会挤爆（上限 30 条）。6 小时窗口足够聊天时提起"我刚刷到"，长期只留真正值得的。

**为什么摘要时抽人物特征**：单独调一次模型抽"谁是什么人"太贵；摘要本来就要读这 24 条，顺手输出 `人物：昵称|特征` 几乎零成本。

## 5. 表情包五维索引

```
主情绪(30 种) → 安全等级(群聊排除 risky) → 强度(1-5, 按回复情绪推算) → 场景加权
```

**为什么不用目录分类**：目录只能表达一个维度。同一张"暴怒"图，强度可能是 4 或 5，场景可能是"被骂"或"群聊玩梗"。五维才能精确匹配。

**为什么强度要推算**：回复"哼"和"你气死我了！"需要的图不一样。基础强度 + 强烈词 + 感叹号，短句且无强烈词则降级。

## 6. 两条链路为什么必须分开

| | QQ 聊天 | B 站 评论 |
|---|---|---|
| 提示词 | 人格库（傲娇、话少） | `COMMENT_STYLE`（外放、喊人来看） |
| 上下文 | 群记忆/人物卡/视频记忆/词库 | **什么都不注入**（直接调 provider，绕过钩子） |
| 长度 | 1–3 条，每条 ≤30 字 | 两句，≤45 字 |

**隔离是靠代码结构，不是靠提示词**：B 站 评论走 `provider.text_chat(system_prompt=COMMENT_STYLE)`，不经过 AstrBot 的 `on_llm_request` 钩子，所以群记忆物理上进不来。

## 7. 规则蒸馏（`feedback_learner`）

```
主人消息 → 关键词粗筛 → LLM 抽规则(规则/范围/类型/风险) → 入库
                                                   │
              每轮注入（聊天最多 6 条 / 评论最多 5 条）
                                                   │
                加权(再说一次+1) / 去重(实体+极性) / 45 天没命中下线
```

**这不是微调**。DeepSeek 只给推理 API，没有微调通道；就算能微调，也需要上万条样本和本地 GPU。规则注入对"改语气/改格式/别做某事"这类需求，效果比微调还直接，而且**可读、可删、可回滚**。

**去重为什么用实体而不是纯字面**：`别用"大肥鱼"称呼我` 和 `不要叫我大肥鱼` 字面相似度只有 0.28，但实体（大肥鱼）和极性（禁令）完全一致——纯字面会漏。

## 8. 守护进程

```
每 30s TCP 探 6185 → 连续 2 次失败 → start _astrbot.bat
   → 等端口通（实测 12-13s）→ guard_report 等 OneBot 连上 → 私聊告知
```

**为什么探端口而不是探进程**：进程存在但卡死（死锁、模型调用悬挂）时，端口探活能发现，进程名判断不能。

**为什么要单实例互斥**：端口锁有竞态（两个进程可能同时 bind 前都通过检查），改用 Windows 命名互斥体 `Global\QQBotWatchdogMutex`。

**为什么用 `AtLogOn` 而不是 `AtStartup`**：SYSTEM 会话里没有用户登录态，QQ 没登录，AstrBot 起来了也没用。

## 9. 已知的坏味道

诚实记录，欢迎修：

- `bili_pusher/main.py` **1888 行**，职责太多（抓取/判据/评论/记忆/指令/日报），应该拆
- 路径 `C:\QQBot` **硬编码 79 处**，靠 `tools/relocate.py` 改写；正确做法是统一 env 配置
- 判据/评论/梗抽取都是**单次 LLM 调用**，没有重试与结构校验（截断时靠逐行格式兜底）
- 表情索引靠**人工 + 视觉打标**，没有一致性校验（同一张图两次打标可能不同）
- `anime_kb` 的命中是**子串匹配**，短词可能误命中（已用长度 ≥2 过滤，但不完美）
