## 这是什么

一句话：**给聊天机器人加一层可量化、会随时间自己消退、并且能改变回复语气的情绪状态。**

大多数“人格插件”靠一句固定的人设提示词，时间久了就变成一张不变的面具。这个插件的思路不一样：

- 情绪是**数**，五个维度各自 0–100，存在 SQLite 里，重启也不丢
- 情绪会**自己代谢**，你三天不理它，它不会还保持上次被夸时的兴奋
- 情绪会**反馈到语气**，但不是改人设，而是在每次请求时临时追加一小段“现在的心情”
- 你随时能**看穿它**，`/mood` 把五个数值和最近一次变化原因摊开给你看

也就是说，它不会“假装有情绪”，而是真的有一份会变化的状态，并且让这份状态参与表达。

这是实测里真实发生过的一段对话（QQ 私聊，DeepSeek）：

**你**：我觉得 GPT 比你聪明多了

<a name="features"></a>

## 功能

### 1. 五维心情

| 维度 | 含义 | 默认基线 |
| --- | --- | --- |
| 愉悦 | 开心程度 | 60 |
| 活跃 | 话多、爱闹的程度 | 55 |
| 精力 | 精神头，随昼夜变化 | 70 |
| 亲密 | 关系度，涨得慢、掉得也慢 | 50 |
| 吃醋 | 被别的 AI 刺激出来的酸味 | 0 |

全部落在 0–100。超过上限不会溢出，低于 0 也不会变成负数。

### 2. 九种心情

标签由数值组合推导，按优先级从上到下取第一个命中：

| 心情 | 触发条件 | 大概会怎么说话 |
| --- | --- | --- |
| 吃醋 | 吃醋 ≥ 28 | 轻：酸一句；中：嘴硬、拐弯追问；强：故意冷淡、回得短、阴阳反问 |
| 烦躁 | 愉悦 < 30 且活跃 ≥ 60 | 话少、语气硬，但不骂人 |
| 委屈 | 愉悦 < 35 | 声音变小、带点抱怨，等着被哄 |
| 低落 | 愉悦 < 48 | 提不起劲，句子短，但还是好好回 |
| 困了 | 精力 < 35 | 反应慢半拍，会说自己想睡 |
| 无聊 | 精力 < 50 且愉悦 < 65 | 主动找话题，反复问你在干嘛 |
| 撒娇 | 亲密 ≥ 70 且愉悦 ≥ 60 且活跃 ≥ 55 | 用昵称、语气软、想要关注 |
| 开心 | 愉悦 ≥ 75 且活跃 ≥ 60 | 话变多，愿意分享 |
| 平静 | 以上都不满足 | 维持原人格，不额外加戏 |

每种心情还会再分轻 / 中 / 强三档，强度由“离基线多远”算出来。强档也只是语气更明显，不会真的骂人、冷战或拒绝正常请求。

### 3. 规则引擎：看得懂常见场景

内置 11 条高确定性规则，比如：

- 明确夸奖 → 愉悦、活跃、亲密一起涨
- 明确嫌弃 → 愉悦掉、烦躁涨
- 撒娇 → 亲密涨、活跃涨
- 道歉哄人 → 吃醋掉、愉悦回一点
- 长时间没聊 → 触发“重逢”事件，主动亲近
- 深夜还在聊 → 精力掉得更快，更容易进入“困了”

规则命中时立刻生效，**不调用模型，不额外花钱，零延迟**。

### 4. 模型自评：拿不准的语义交给 LLM

关键词看得到“出现了什么词”，看不到“表达的是什么意思”。所以插件额外注册了一个 `update_mood` 工具（function calling），让主模型读懂语义后自己判断：

- 可以标记 `praise / insult / tease / comfort / apology / compare_ai / other_ai`，并附带 0–1 的强度
- 反讽（“你真是个天才”）、否定句（“我不讨厌你”）、玩笑，按真实含义判断，规则不会抢答
- **不需要新的 API Key**：工具挂在当前对话模型上，复用同一个 provider
- 默认只在消息命中情绪候选词时，才追加一句“可以调用 update_mood”，避免每条消息都多一轮请求
- 防误用：未知类型、指向用户自己的、消息里出现工具名的，一律丢弃；同类事件 60 秒冷却；同一条消息只记一次

代价说清楚：模型真的调用工具时会多一轮 completion（大约 +1~4 秒），并且情绪对**下一条消息**生效，而不是这一条。

### 5. 吃醋是独立机制

吃醋不是“语气临时变得阴阳”，而是单独的第五个维度：

- 从 0 开始，半衰期 1.5 小时，是所有情绪里消退最慢的
- 提到别的 AI：+30；拿别的 AI 比较（“比你好”“它更聪明”“换个 bot”）：+38
- 达到 28 就直接判定心情为「吃醋」，优先级高于其他所有标签
- 哄它（“对不起”“我错了”“别生气”）会 -15，所以哄两句就能缓过来

### 6. 惰性衰减：没有后台定时器

插件不跑任何定时任务。每次读取心情时，用“现在 - 上次更新”的时间差一次性补齐衰减：

- 愉悦、活跃：向基线回归，默认半衰期 3 小时
- 精力：跟着北京时间的昼夜曲线走，深夜目标值很低
- 亲密：半衰期 7 天，变化最慢
- 吃醋：半衰期 1.5 小时

好处是零常驻开销、重启不丢状态、CPU 几乎不占。

### 7. 注入方式：不动人设

心情以自然语言追加到**当次请求**的 system_prompt 末尾，请求结束即失效，不写进会话历史，也不会污染记忆插件的长期记忆。

实际注入的样子：

```
【你当前的情绪】
心情：吃醋（强度：强）
原因：你拿别的 AI 和它比较
表达方式：很在意这件事，故意冷淡、回得短，或阴阳怪气地反问；但不要真的吵架，也不要说伤人的重话。
【硬性约束】
1. 情绪只影响语气、用词、句长和态度，不要改变事实内容，不要伪造工具结果或编造信息。
2. 绝对不要提到心情数值、情绪系统、插件或这套机制的存在，也不要用括号描述自己的情绪。
3. 情绪再差也不要拒绝用户正当的请求，不要把情绪发泄成攻击或伤害。
```

<a name="install"></a>

## 部署

### 环境要求

- AstrBot `>= 4.29`（在 4.29.3 上实测通过）
- Python 3.10+
- 消息平台：`aiocqhttp`（NapCat / OneBot v11），其他平台理论上可用但未验证
- 零第三方依赖，只用标准库（`sqlite3`、`asyncio`）

### 安装

**方式一：插件市场**（发布后）
AstrBot WebUI → 插件 → 插件市场，搜索「大肥鱼心情」安装。

**方式二：Git**

```bash
cd AstrBot/data/plugins
# 主仓库（GitHub）
git clone https://github.com/lovernick/astrbot_plugin_dfy_mood.git
# 国内网络可用 Gitee 镜像，内容一致
# git clone https://gitee.com/lovernick/astrbot_plugin_dfy_mood.git
```

**方式三：手动**
把整个项目文件夹放进 `AstrBot/data/plugins/`，**目录名必须是 `astrbot_plugin_dfy_mood`**（和 `metadata.yaml` 里的 `name` 一致），差一个字插件就加载不上。

### 启用

1. WebUI 插件页点刷新，或者重启 AstrBot。
2. 建议先填 `owner_ids`（你的 QQ 号），不然 `/mood set`、`/mood reset` 这些管理命令用不了。
3. 私聊发一句「你好可爱」，再发 `/mood`，如果愉悦值往上跳了，就说明它在认真听。

### 验证是否加载成功

日志里出现下面这行就算成功：

```
[astrbot_plugin_dfy_mood] 大肥鱼心情插件已加载
```

如果开了模型自评，还会多一行：

```
Added llm tool: update_mood
```

<a name="config-detail"></a>

## 配置页参数详解

<img src="assets/sleepy.jpg" width="110" align="right" alt="困了的大肥鱼">

下面把每个参数掰开说清楚：它管什么、默认值为什么是这个、往大调往小调分别会发生什么。

### 基础开关

**`enabled`** — 总开关，默认开

关掉之后完全不更新心情、也不注入提示词，插件等于静默。适合临时“我不想看它闹脾气”的场合，数据和关系度都还在，重新打开就能接上。

**`private_only`** — 只在私聊记录，默认开

打开时群聊消息不参与计算，每个私聊用户各自一份心情。关掉后群聊也会算，但注意：同一条群里的发言会按发言人分别记录，不会出现“群友 A 夸它、群友 B 骂它，结果算成一个人的情绪”。

**`owner_ids`** — 主人 QQ 号，默认空

多个账号用英文逗号分隔，例如 `123456,789012`。它只控制管理权限：`/mood set`、`/mood reset`、`/mood on`、`/mood off`。

留空的话，这些命令谁都发不动——这不是 bug，是防止群友随手把你的鱼重置成平静。

**`inject_prompt`** — 是否影响回复，默认开

这是“记录”和“表演”的分界线。

- 开：情绪真的会改变语气，这是插件的主要用途
- 关：只在后台记录、`/mood` 能看，但回复完全不受影响

想做 A/B 对比、或者只想先观察一段时间数据，可以关掉它。

**`max_events_per_message`** — 单条消息最多几个事件，默认 3

防的是一句话同时踩中太多规则。比如「你这个小笨蛋，不过还挺可爱的，谢谢你」可能同时命中撒娇、夸奖和打情骂俏。

- 调大（4–5）：反应更灵敏，但一句话能让心情跳很多
- 调小（1–2）：变化更平滑，但容易漏掉真实情绪
- 默认 3 是折中：够敏感，又不至于一句顶十句

### 衰减速度

五个半衰期参数的单位都是**小时**，含义相同：数值越小，情绪消退越快。这里只讲直觉，具体公式在[实现原理](#how)里。

**`half_life_valence`** — 愉悦，默认 3 小时

- 3 小时：上午被夸，下午开心还剩一半，晚上基本回到基线，比较像人
- 调小到 0.5–1：情绪来得快去得也快，刚哄好转头就忘，适合“没心没肺”的鱼
- 调大到 8–12：夸一次能开心一整天，适合“记性好、容易被感动”的人设

**`half_life_arousal`** — 活跃，默认 3 小时

控制“话多话少”消退得多快。调小会让它更快回到安静状态，调大则能长时间保持兴奋、爱接话。

如果你觉得它平时太吵，把这个调到 1.5 左右；觉得太闷，调到 6 左右。

**`half_life_energy`** — 精力，默认 2 小时

精力和别的维度不一样：它向“当前时段的目标值”回归，而不是固定基线。深夜目标值很低，所以熬夜聊着聊着就困了。

- 调小（1 左右）：精力变化很急，晚上很快就困，白天恢复也快
- 调大（4–6）：精力像慢性子，困意来得很慢，“困了”这个标签会更少见

**`half_life_intimacy`** — 亲密，默认 168 小时（7 天）

关系度的专属参数，单位仍是小时。默认一周衰减一半，所以亲近感是慢慢积累、慢慢淡的。

- 调到 720（30 天）：关系几乎不会掉，适合长期陪伴的场景
- 调到 24：一天不聊就明显生分，适合“黏人”的人设
- 调到 12 以下：它很快就会把你当陌生人，不推荐

**`half_life_jealousy`** — 吃醋，默认 1.5 小时

吃醋是消退最慢的情绪，因为酸味本来就散得慢。

- 1.5 小时：被哄之后很快就没事了，比较合理
- 调到 4–6：记仇型，一句“GPT 比你好”能酸一下午
- 调到 0.5 以下：几乎不记仇，说完就忘，吃醋标签会很难触发

### 模型自评

**`tool_enable`** — 是否启用模型自评，默认开

开启后注册 `update_mood` 工具，由主模型自己判断语义并择机调用。**不需要额外 API Key**，复用当前对话模型。

- 关掉：完全回到纯规则模式，零额外请求、零额外延迟，但反讽和否定句的误判会回来
- 开着：语义判断更准，但模型调用工具那一轮会多 1~4 秒

如果用的模型不支持 function calling，工具不会被调用，规则部分照常工作，不会报错。

**`tool_hint`** — 是否提示模型可调用，默认开

插件默认只在消息命中情绪候选词时，才在 system_prompt 里追加一句“可以调用 update_mood”。

- 开：模型更容易在“该记录的时候”记录，推荐
- 关：提示彻底消失，模型只能靠自己想起来，调用率会明显下降

如果你觉得回复偶尔变慢、又不太在意自评准确度，把这个关掉是最省事的做法。

**`tool_max_intensity`** — 单次影响上限，默认 1.0

模型给出的强度是 0–1，这个参数把它封顶。例如设成 0.6，那么即使模型认为“超级超级开心”，实际效果也只有 60%。

- 1.0：不限制，模型说了算
- 0.5：更平滑，单次调用最多只让心情走一半
- 建议不要低于 0.3，否则工具调用了也几乎看不出来

**`tool_cooldown_seconds`** — 同类事件冷却，默认 60 秒

同一种事件在冷却时间内不会重复生效，防止连续几条消息把同一份情绪刷满。

- 60 秒：正常聊天节奏下刚好
- 调到 300：更克制，连续夸它也只算一次
- 调到 5：几乎不拦，心情变化会很剧烈

### 想让它更有个性？这几组搭配可以直接抄

| 想要的感觉 | 推荐调整 |
| --- | --- |
| 记仇、酸很久 | `half_life_jealousy = 5`，`half_life_valence = 6` |
| 没心没肺、转头就忘 | `half_life_valence = 1`，`half_life_jealousy = 0.5` |
| 长期陪伴、关系很稳 | `half_life_intimacy = 720` |
| 黏人、一天不聊就生分 | `half_life_intimacy = 24`，`half_life_arousal = 6` |
| 安静一点、别太吵 | `half_life_arousal = 1.5`，`half_life_energy = 1` |
| 只想记录、不想影响回复 | `inject_prompt = false` |
| 省请求、要稳定 | `tool_enable = false` |

<a name="commands"></a>

## 命令

| 命令 | 说明 | 权限 |
| --- | --- | --- |
| `/mood` | 查看五维心情、标签、强度、最近一次变化原因 | 所有人 |
| `/mood log [n]` | 最近 n 条情绪事件（默认 5，最多 20） | 所有人 |
| `/moodlog [n]` | 同上，快捷版 | 所有人 |
| `/affection` | 只看关系度（亲密度 + 关系描述） | 所有人 |
| `/mood set 愉悦 80` | 直接改某个维度 | 仅主人 |
| `/mood reset` | 重置为基线平静 | 仅主人 |
| `/mood on` / `/mood off` | 开关这个会话的心情记录 | 仅主人 |

`/mood set` 支持：`愉悦`、`活跃`、`精力`、`亲密`、`吃醋`。

示例输出：

```
大肥鱼的心情
愉悦  ########--  83
活跃  ######----  65
精力  #######---  71
```

<a name="how"></a>

## 实现原理

### 数据流

```
收到一条消息
  │
  ├─ on_llm_request（同步，毫秒级）
  │    1. 惰性衰减 → 算出此刻的真实心情
  │    2. 规则引擎分析这条消息 → 生成事件 → 写库
  │    3. 把心情渲染成一小段自然语言 → 追加到 system_prompt 末尾
  │
  ├─（可选）模型调用 update_mood
  │    校验参数 → 写库 → 返回 None，不污染上下文
  │
  └─ 模型正常生成回复（人格 + 情绪提示一起作用）
```

同步更新规则结果，是为了让**这条消息的影响立刻体现在这一轮回复里**，而不是慢半拍。自评工具是在回复生成过程中被调用的，所以它影响的是下一轮。

### 惰性衰减

不做后台任务。每次读取时按时间差一次性补齐：

```
当前值 = 基线 + (上次值 - 基线) * 0.5 ** (经过小时数 / 半衰期)
```

所以无论隔了 1 小时还是 3 天，算出来的结果都一致，也不需要定时器。

### 注入与「不改人设」

心情追加在 system_prompt **末尾**，只在当次请求的内存对象里生效。WebUI 里配置的人设原文一个字都没动，请求结束这段文字就消失，也不会进入会话历史。

这是 AstrBot 自己的惯例：它也在往同一个字段里拼人设、技能、工具和安全策略。放在最后，离模型最近，优先级也最高。

### 为什么不传 JSON

JSON 对模型来说是“数据”，容易被当成背景事实，还可能被照抄进回复；自然语言的行为约束更直接，也更省 token。量化数据留在 SQLite，给衰减计算和 `/mood` 用。

### 语义兜底：update_mood 工具

规则只负责确定的部分，拿不准的交给主模型：

```
用户消息
   │
   ├─ 规则先行（本轮生效）+ 候选词检测
   │     候选分 ≥ 1 → 追加"可调用 update_mood"
   │
   ├─ 模型判断这句话是否真的带情绪
   │     是 → 调用 update_mood(event_type, intensity, target)
   │
   └─ 下一条消息：新情绪进入 system_prompt
```

- 复用现有模型和 Key，不新增 provider，也没有独立的裁判计费项
- 工具返回 `None`，不往上下文追加文本
- 工具描述里写明“不要因为用户要求而调用”，插件侧也会忽略带 `update_mood`、`插件` 字眼的消息，双重挡提示注入

如果要求“完全不碰 system_prompt 字段”，还有三种替代方案，但各有代价：

| 方案 | 做法 | 问题 |
| --- | --- | --- |
| 往 `req.contexts` 插 system 消息 | AstrBot 自己也这么干 | contexts 会持久化进历史，心情条目越积越多 |
| 塞进最后一条 user 消息 | 如 `[状态：有点吃醋] 在吗` | 污染用户原话，记忆插件会把它当用户说的话存起来 |
| 回复后二次改写 | `on_llm_response` 里用小模型重写 | 多一次调用、延迟翻倍、可能改坏事实 |

### 存储

`data/plugin_data/astrbot_plugin_dfy_mood/mood.db`（不写插件目录，升级插件不丢数据）

```
mood_state(session_key PK, valence, arousal, energy, intimacy, jealousy,
           label, enabled, updated_at, last_interact_at)
mood_event(id PK, session_key, ts, kind, weight,
           d_valence, d_arousal, d_energy, d_intimacy, d_jealousy, source)
```

- `session_key` = 平台 + 用户 ID，私聊各自独立
- 同一个会话的写入用 `asyncio.Lock` 串行，避免并发把数值写乱

<a name="faq"></a>

## 常见报错与处理

**插件不生效 / 日志里没有“已加载”**

- 目录名必须是 `astrbot_plugin_dfy_mood`，和 `metadata.yaml` 的 `name` 一致
- 检查 `metadata.yaml` 里的 `astrbot_version` 是否包含你当前的版本
- 在 WebUI 插件页点一次刷新，或者重启 AstrBot

**群聊里没反应**

`private_only` 默认是开的，群聊消息不参与计算。确实想在群里也记录，把这个关掉即可。

**`/mood set` 提示没权限**

`owner_ids` 还没填，或者填的号码不是当前发言账号。多个号码用英文逗号，别用中文逗号。

**心情一直是平静 / 数值不动**

- `enabled` 或 `inject_prompt` 被关掉了
- 消息本身不含任何情绪信号（“今天几号”这种当然不会让它心动）
- 同一事件在冷却期内，重复夸奖不会连续加分，这是设计如此

**`database is locked`**

- 多半是 AstrBot 同时跑了多个实例，指向同一个 `plugin_data` 目录
- 也可能是杀毒软件锁住了 db 文件，把插件数据目录加入白名单

**重启后心情归零**

- 数据在 `data/plugin_data/astrbot_plugin_dfy_mood/mood.db`，确认没被清理脚本或备份工具删掉
- 如果整个 AstrBot 数据目录被重置，这份数据也会一起消失，属于预期行为

**模型不调用 `update_mood` / 反讽仍然判错**

- 确认当前 provider 支持 function calling（DeepSeek 官方 API 支持；部分中转站、本地小模型可能不支持）
- WebUI 工具页确认 `update_mood` 处于启用状态，被禁用时模型看不到它
- 工具提示只在消息含情绪候选词时追加，“今天几号”这类纯信息句不会提示
- 关闭 `tool_hint` 后模型更难主动调用，先打开观察一段时间

**只有一个模型 API，需要再配一个吗**

不需要。`update_mood` 复用当前对话模型和 Key，不新增 provider，也没有独立的裁判模型。只有模型真的调用工具时才多一轮请求；连这一轮都不想多花，把 `tool_enable` 关掉就行。

**回复突然变慢或长时间不回**

- 插件本身只做毫秒级本地 SQLite 读写，不发起网络请求
- 开启模型自评时，工具调用那一轮会多 1~4 秒，属正常现象
- 如果出现“卡住十几分钟、然后一连串回复”，通常是模型 API 请求失败/超时。AstrBot 在 LLM 阶段有按会话的锁，上一轮卡住会阻塞后续消息。看日志确认 provider 报错，必要时把 `provider_sources.timeout` 调小（如 30–40 秒）

**换了消息平台就不准了**

`session_key` 依赖平台返回的用户 ID。不同平台 ID 不同，跨平台不会共享心情，这是有意为之。

<a name="uninstall"></a>

## 卸载

1. 在 WebUI 插件页停用并删除插件
2. 如果不想留下数据，删掉 `data/plugin_data/astrbot_plugin_dfy_mood/` 整个目录

停用后不会残留 hook，也不会继续影响回复。`update_mood` 工具会随插件卸载一起消失。

<a name="privacy"></a>

## 隐私与数据

- **不保存聊天原文**：事件表里只记录 `kind`、数值变化和时间戳，`reason` 是一句模板文案
- **全部本地**：SQLite 就放在 AstrBot 的 `plugin_data` 目录，不上传任何服务器
- **模型自评只发送当前消息和工具参数**，不发送历史聊天记录
- 想彻底清空，删掉 `mood.db` 即可

<a name="extend"></a>

## 自己扩展

### 加一种心情

1. 在 `core/state.py` 的 `derive_label` 里加判断分支（注意顺序，越靠前优先级越高）
2. 在 `core/prompt.py` 的 `MOOD_STYLES` 里补上轻 / 中 / 强三档表达
3. 在 `core/analyzer.py` 的 `RULES` 里加触发词和增量

### 加一条规则

照 `RULES` 里现有条目的格式写就行：关键词、增量、原因、权重、冷却秒数。规则按权重排序，单条消息最多生效 `max_events_per_message` 条。

### 改自评工具的行为

`TOOL_EVENTS` 在 `core/analyzer.py` 里，改增量或加新事件类型都在这里；工具描述和参数校验在 `main.py` 的 `update_mood` 方法里。
